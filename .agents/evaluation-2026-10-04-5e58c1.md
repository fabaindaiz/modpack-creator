- **Better than the default.**
  1. **A document table is the test's specification.** `## Acciones y roles` in `docs/decisions.md` is parsed by `tests/test_routes_roles.py`. The operator rows must equal `OPERATOR_METHODS`, every write route must reach a row, every auditing method needs a row, and a malformed row fails.   2. **A "Foco de revisión" section in each plan.** It lists edge cases that no task would cover, gives each one to an owning task, and gives each a test.
  3. **Two-way ratchet baselines.** "una entrada que ya no viola también falla" (`LAYERING_BASELINE`, `IDEMPOTENT_POSTS`): a baseline cannot hold stale exemptions.
  4. **The visual sweep was proven to bite.** It was run against the previous `app.js` ("6 problemas"). That is a mutation check of a tool rather than of a test.

## Working process this session
**What worked.**
- **The whole-branch final review was the most productive step.** It found 2–3 Important defects per plan that the task reviews missed: B unreachable after a failed A, a finished rollback offered again, the unquoted time silently turning the schedule off, the eager 10 s preview, an update that silently dropped a pending rollback, and a missing path for MongoDB 4.4 and older. All of these are defects that span tasks or depend on the environment, so a diff-scoped review cannot see them.
- **Rulings became rung 3, not prose.** R1+R8 became the role-table test, and R6 became `tests/test_operator_typing.py`. The unquoted-time fix has its regression test in `tests/test_update_schedule.py`.
- **No agent worked around the deny**, and every leftover process was cleaned up.

**What cost too much.**
1. **Rulings came after execution.** 18 controller rulings were reviewed one by one after plan 1, most were changed, and the result was an 11-task addendum. One example: R14 brought back two buttons that plan 1 had replaced with "simular → ejecutar", which shows in the commits `208a6e1` and then `18d2e52`.
2. **Fix rounds.** 28 `fix:` commits against 21 `feat:` commits, with fix rounds in about 4–6 tasks per plan (controller's figure; the ledgers were deleted, so it cannot be recounted).
3. **The red gate added overhead to every task**, and an implementer skipped the full suite, so the controller had to re-run it.
4. **Large diffs were only partly read by reviewers.**
5. **Two API session-limit interruptions.** ASSUMPTION: they are linked to running three plans in one session, against the "one item per session" rule.

**Did the instruction system help?**
- It helped where it was executable: the audit, the startup test, the network block and the role table.
- It hindered in three ways:
  - the stale snapshot given to subagents;
  - a "gate must pass" rule that could not pass, patched in each plan instead of at the source;
  - a `verify` skill that is stale and does not mention `test-mongo.sh` or the visual sweep for `src/web/`.
- The commit rule is prose (rung 1) under constant pressure: this evaluator's own harness prompt asked for a `Co-Authored-By` trailer. It held, with 0 of 74 commits carrying one.
