# Proposal: validate-each-transformation-run

A one-line command whose quoting the shell reinterprets edits text nobody asked to change, and still reports success. Backticks inside a double-quoted inline script are command substitution: the shell runs them and the word between them vanishes from the text being written. A regular-expression replacement over prose can likewise damage a sentence that merely resembles the pattern. The damage shows only in the diff, so every such edit is read in the diff before it is accepted, and scripts and long texts go to a file written with the editor tool, not into a quoted command line.

## Evidence

One carrier, one owner. A single-line inline script with backticks in its text silently removed one word of a code comment in three separate sessions, each time restored by hand after reading the diff, although the cause was noted in the log after the first one; and a regular-expression replacement spoiled a sentence of a manual. Each command exited with success. An earlier related slip in the same log, two edits by line number landing on the wrong lines after a previous edit shifted them, was caught by the type checker and the role sweep, not by the editor, after which only replacements by text with a check were used. Literature: the candidate's own; no new source consulted.
