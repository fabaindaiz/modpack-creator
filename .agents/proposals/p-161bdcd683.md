Updating one key of a nested map by reading the whole record, changing the key in memory and writing the map back loses a concurrent update to another key of the same map; the per-key fix is an atomic update of that key's dotted path, and a batch of keys is one update with several dotted paths.

## Evidence

2026-10, in a small web service: a per-record map of decisions was saved by a read-modify-write through a generic patch; a task review found that two decisions saved at the same time would keep only one. It became one atomic dotted-path update per key, and later a bulk form writing several keys in one update.

### Literature

This is the lost-update anomaly, P4 in Berenson et al., "A Critique of ANSI SQL Isolation Levels", SIGMOD 1995 (https://dl.acm.org/doi/10.1145/223784.223785). Refused: textbook, and an agent knows it; the part that is not textbook — that a nested value sent through a partial update replaces the map whole and only the emitted keys show it — is `nested-partial-update-replaces`, for which this harvest records an experiment instead.
