A startup test that imports the whole application under the minimum supported interpreter, with placeholder configuration and no network, then checks that every dependency-injection binding passes a constructor the types it declares.

## Result

2026-10, in a service that cannot boot where it is written (it needs a document store, an identity provider and a remote control panel that only the deployment host reaches). Run once, it caught two composition failures that no existing check saw. First, an import-time NameError from a return annotation naming a class that was never imported: invisible on the newer interpreter on the developer's machine, because it defers annotation evaluation, and fatal on the deployed one. Second, a service wired with the wrong repository class, which would only have failed when an endpoint was called. A type checker run at the same time found the first failure but not the second. Cost: minutes. Verdict confirms the note: the dominant bug class was composition, and a resolved-graph startup with stand-ins catches it before deploy.
