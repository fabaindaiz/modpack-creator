A header-building chain in which each step mutates the mapping it receives turns a per-client credential into process-wide state when the chain starts from a shared default mapping. The authorization header of one client then travels with every later request of every other client, to other hosts. Not when each step returns a new mapping, or when no default mapping exists.

## Evidence

2026-10: an HTTP client base class whose request method took a header mapping with an empty-mapping default, then merged the session headers, the content-type header and the authorization header into it in place. A test against a local server confirmed the effect. After one request from a client holding a token, a second client configured with no authorization sent the first client's bearer token. Literature: the language reference states that default values are evaluated once, when the function is defined, so a mutable default is shared by every call (https://docs.python.org/3/reference/compound_stmts.html#function-definitions). The mechanism is textbook. What this adds is the consequence: a credential crossing to a third party.
