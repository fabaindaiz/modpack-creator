An upstream "latest version" query answers the newest by publication date among the filters it is given, which can be older than the installed version when that one came through a wider filter (a less stable channel); an updater that takes it, or a resolver that prefers the most stable channel first, moves an installed component backwards. Compare every candidate with what is installed and never choose one published before it, except by an explicit pin.

## Evidence

A dependency resolver preferring the most stable channel, then the newest, replaced an installed pre-release with an older stable release once a stable one fitted; a daily update check announced that older release as an update. The owner's rule became that a component never goes back. The fix passes, per component, every version installed or built as floor candidates; the resolver takes the newest that fits the target as the floor and only versions published at or after it. Mixed time zones between stored and fetched dates had to be normalised first.
