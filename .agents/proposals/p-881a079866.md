# Proposal: fix-at-the-call-site-leaves-the-others

A store that returns timestamps without their zone, normalised by a helper called at each read, breaks again at every read path added later: the helper reaches the call sites somebody remembered. The fix belongs at the store boundary (a client or mapper option that makes every read carry its zone, or one conversion in the shared reader), with a test that reads each record kind back from the real store and compares it with an aware value.

## Evidence

One carrier, one owner; the queued candidate's first occurrence was in another repository of the same owner. A document store hands timestamps back without a zone; a normaliser is called at about forty read sites. The session log records three occurrences in about a month, each fixed at its call site: a second scan that read every item as changed, a floor comparison mixing aware and naive values, and a page that failed with a server error as soon as one record of a new kind existed, found as critical by a clean-context review because the real-store tests held no record of that kind. The in-memory doubles keep the zone they are given, so the default gate stayed green every time; this also gives the queued `a-double-cannot-show-what-it-does-not-model` the real-store run it lacks. ASSUMPTION, to verify against the driver's documentation: the driver offers a connection-level option for zone-aware reads.
