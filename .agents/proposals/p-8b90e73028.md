# Proposal: a-check-must-be-seen-to-fail

Where the red run of a test is slow, or an earlier step of the gate stops before the test's assertion runs, test-first slips: the code is written first so the run can get past the earlier step. Two remedies hold. Before: write the signature alone (a stub), so the type checker passes and the test goes red on its assertion. After a slip: remove the fix in a throwaway copy of the branch, or break the rule by hand, and watch the test go red there; a test that stays green under that removal is not evidence.

## Evidence

One carrier, one owner. Tests written with or after their code were recorded in at least four sessions of the period, for the same causes each time: the suite against the real store takes minutes, and the type checker runs before the tests and fails on a missing signature. The stub-first step was used each time it was remembered. After a slip, four real-store tests were confirmed by removing their fixes in a disposable copy of the branch, and three rules broken by hand turned four tests red, as they should. This restates the owner's global test-first instruction, so it counts as one occurrence; the new part is the two remedies.
