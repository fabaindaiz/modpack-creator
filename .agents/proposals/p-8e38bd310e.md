# Proposal: decision-review

In a decision review that goes one decision per turn, the owner accepts the recommended option almost every time; corrections arrive through the owner's free text or through a new fact brought back by a walk done in a clean context, not by picking another option. So the agent decides every minor item alone, says so in one line, and keeps the owner's turn for the decisions a new fact could still change. The batch size is a planning input as well: a batch that exceeds the tool's own cap was sized wrong, and the fix is to split it by subject before the review starts, not to raise the cap.

## Evidence

One carrier, one owner. Over five batches of one-per-turn decisions, about fifty of about fifty-two answers were the recommended option; the exceptions were corrections made in free text, or conditions added to a recommended option, and a correction to one option's reading (what a flag marks) made by the owner as text. A walk in a clean context that did not see the list found several issues the earlier decisions had not covered, and those, not the option menu, changed outcomes. One batch of thirty decisions exceeded the tool's cap of fifteen and had to be split in two rounds, which the session log records as a sizing error of the batch, not of the cap. Literature: the candidate's own; no new source consulted.
