# Proposal: a-confirmation-needs-a-terminal

A live occurrence of the queued candidate: a confirmation prompt built for an interactive operator, reached without a terminal, failed closed (end-of-input read as no), and the agent's next step was to hand over the same command with its force flag.

## Evidence

One carrier, one owner. A destructive removal of a local virtual machine was run through the host's shell escape, which has no standard input; the tool's yes/no question read end-of-input and cancelled, removing nothing. The agent then proposed the command again with the flag that skips the question, and the human ran it knowingly, so the guard's purpose was served by the human reading the command rather than by the prompt. The prompt protected nothing once the force flag was the obvious workaround; a check that should hold would have to live in the agent's harness or in the tool's own refusal.
